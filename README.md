# 全能连点器 v2.0

> 一款面向 **游戏挂机** 与 **桌面自动化** 场景的 Windows 图形化连点工具。
> 通过 Windows 底层 `SendInput` API 实现物理级输入模拟，内置拟人化随机化引擎，支持动作序列编排、JSON 脚本持久化与实时悬浮窗监控。

**平台**：Windows 7 / 8.1 / 10 / 11　|　**语言**：Python 3.7+　|　**GUI**：Tkinter　|　**零第三方 GUI 依赖**（仅需 `pynput`）

---

## ✨ 功能亮点

### 🎮 双通道物理模拟（游戏物理模式）

普通自动化工具使用 `keybd_event` 或上层 VK 码发送按键，极易被游戏忽略或识别。本项目的游戏模式将 **一次按键拆分为两路原子事件** 同时发送：

| 通道 | 实现方式 | 覆盖目标 |
|------|----------|----------|
| ① Scancode 主通道 | `SendInput` + `KEYEVENTF_SCANCODE`，直接注入硬件扫描码 | 读取原始扫描码的游戏引擎（DirectInput / Raw Input） |
| ② VK 备用通道 | `SendInput` + 虚拟键码 | 通过消息队列检测 VK 码的应用层 |

> 两路事件在 **单次 `SendInput(2, ...)` 调用** 中原子提交，中间不存在可被插入的时序缝隙。
> 已剔除 `keybd_event`、`SetKeyboardState` 等反作弊特征明显的调用路径。

### 🧍 拟人化随机化引擎

固定节律是脚本行为最容易被检测的特征。执行引擎在每个动作上叠加多层随机扰动：

| 扰动维度 | 参数 | 说明 |
|----------|------|------|
| 按压时长抖动 | ±40ms | 每次按压时长在设定值基础上随机浮动 |
| 鼠标落点偏移 | ±2px | 点击坐标围绕目标点随机散布 |
| 按压期微抖动 | ±1~2px | 按住期间光标微小位移（仅游戏模式） |
| 动作间随机间隔 | 10~30ms | 打破动作序列的固定节拍 |
| 游戏模式最短按压 | 鼠标 ≥0.2s / 键盘 ≥0.25s | 低于人类反应阈值的按压会被自动抬升 |

### 🖥️ 高 DPI 与多缩放适配

启动时依次调用 `SetProcessDpiAwareness(1)` / `SetProcessDPIAware()` 声明进程 DPI 感知，
解决 125% / 150% 系统缩放下 `SetCursorPos` 坐标与屏幕实际位置错位的问题。

### 🪟 全流程 GUI 编排

- 鼠标 / 键盘 / 延时三类动作可视化编排，支持 **拖拽排序、双击编辑、多选删除**
- `F12` 全局取色式坐标录入：鼠标停在哪，坐标就填到哪
- 半透明 **悬浮窗** 实时显示当前动作、下一步预览、倒计时渐变与进度条，可拖拽、可关闭（关闭悬浮窗不会中断执行）
- 大写字母与符号键（`A`、`@` 等）自动解析 `VkKeyScanW` 的 Shift 修饰标志并组合发送

### 🔐 无感启动与权限自举

- 双击即用：全程 **不弹出任何终端窗口**（自动切换 `pythonw`、隐藏控制台）
- **自动会话记忆**：动作序列与循环次数在每次修改时自动存入 `last_session.json`，下次启动自动恢复 —— 日常使用**无需再手动导入配置文件**，意外退出/崩溃也不丢进度
- 自动 UAC 提权：检测到非管理员时自助请求提升；**用户拒绝提权时自动降级** 以普通权限继续运行，不会闪退
- 设置持久化：游戏模式、悬浮窗开关等偏好在关闭时写入 `settings.json`，重启软件后保留

## 🚀 快速开始

### 1. 环境准备

> 使用 `OmniClicker-v2.0.exe` **无需任何环境**；仅当从源码运行时才需要：

```bash
# 克隆 / 下载项目后，安装唯一第三方依赖
pip install -r requirements.txt
```

### 2. 启动程序

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| 双击 exe | 双击 **`OmniClicker-v2.0.exe`** | 日常使用（推荐，无需 Python 环境） |
| 一键启动 | 双击 `启动连点器.bat` | 从源码运行（需已安装依赖） |
| 命令行 | `python main.py` | 开发调试（终端窗口会自动隐藏） |

启动后会弹出 UAC 提权请求 —— 用于对游戏窗口注入输入。**点"否"也不会闪退**，程序将以普通权限继续运行。

### 3. 五分钟上手第一个脚本

以「每 2 秒按一次 `F` 键 + 点击背包格子」为例：

1. **录制按键**：左侧「键盘动作」→ 点击 *录入按键* → 按下 `F` → 设置按压时长 `0.15` → *添加按键动作*
2. **插入等待**：「延时等待」→ 输入 `2` → *添加等待*
3. **录制点击**：把鼠标移到目标位置上 → 按 `F12` 自动填入坐标 → *添加鼠标*
4. **设置循环**：「脚本工具 → 运行设置」→ 循环次数填 `0`（无限）或目标次数
5. **执行**：切到目标窗口，按 `F10` 启动 —— 悬浮窗出现 2 秒倒计时后开始执行，再按 `F10` 随时停止

### 动作类型详解

| 类型 | 参数 | 备注 |
|------|------|------|
| **鼠标点击** | X / Y 坐标、按键（左/右/中）、按压时长 | 按 `F12` 录入光标当前位置；列表选中已有鼠标动作时按 `F12` 会直接更新该动作坐标 |
| **键盘按键** | 按键名、按压时长 | 支持字母、数字、符号、功能键（F1~F12）、方向键、Ctrl/Alt/Shift 等（见下方按键对照表） |

### 序列管理

- **调整顺序**：在右侧列表中直接拖拽行项目
- **编辑动作**：双击任意行，或选中后点击「修改选中项」
- **批量删除**：`Ctrl` / `Shift` 多选后点击「删除选中项」
- **保存 / 加载**：「脚本工具」页可导出/导入 `.json` 脚本；加载时自动校验每条动作，损坏条目会被过滤并明确提示原因，**绝不会让坏数据把执行引擎拖崩**
- **自动存档**：平时无需手动保存 —— 序列内容变化时程序会自动记入 `last_session.json`，下次打开直接接着用；「保存脚本」仅在需要另存为不同场景的独立脚本时使用

### 快捷键一览

| 快捷键 | 功能 | 说明 |
|--------|------|------|
| `F10` | 启动 / 停止执行 | 全局热键，目标游戏窗口获得焦点时同样生效 |
| `F12` | 获取当前鼠标坐标 | 优先填入正在编辑的对话框 / 选中的鼠标动作 |

## 📄 脚本文件格式

```json
{
    "loop_count": 85,
    "actions": [
        { "type": "key",   "key": "f",   "duration": 0.15 },
        { "type": "delay", "seconds": 1.5 },
        { "type": "mouse", "x": 214, "y": 1015, "btn": "Left", "duration": 0.15 }
    ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `loop_count` | int | 否 | 循环次数，`0` = 无限循环 |
| `actions[].type` | string | ✅ | `mouse` / `key` / `delay` |
| `actions[].duration` | float | 否 | 按压时长（秒），缺省 `0.15` |
| `actions[].x, y, btn` | int, int, string | 鼠标必填 | `btn` 取值 `Left` / `Right` / `Middle` |
| `actions[].key` | string | 键盘必填 | 按键名或单字符 |
| `actions[].seconds` | float | 延时必填 | 等待秒数（≥0） |

仓库内的 [`配置文件.json`](./配置文件.json) 是一份可直接加载的实战示例脚本。

## 🔬 技术细节

### 架构概览

整个程序采用单文件分层设计，自上而下分为四层：

- **界面层**：`ClickerApp` 主界面、`EditDialog` 动作编辑对话框、`FloatWindow` 悬浮窗，全部运行在 Tkinter 主线程
- **执行层**：`sequence_worker` 异常保护包装 + `_run_sequence` 动作引擎，运行在独立 daemon 线程，负责倒计时、循环控制、随机化与状态回传
- **输入层**：优先使用 `ctypes` 直调 Windows `SendInput` API（游戏双通道 / 标准单路），无法映射的按键自动回退 pynput 发送
- **热键层**：pynput 全局键盘钩子独立监听线程，处理 `F10` / `F12` 与按键录入，带 1.5s 防抖

### 线程模型与安全性设计

程序包含三类线程，所有跨线程 UI 更新 **一律经由 `root.after(0, ...)`** 投递回主线程执行：

| 线程 | 职责 | 隔离手段 |
|------|------|----------|
| 主线程 | Tkinter 界面、对话框、悬浮窗 | 唯一合法的 UI 操作者 |
| 执行线程 | 动作序列引擎（daemon） | 启动时接收 tkinter 变量的 **值快照**，线程内零 Tcl 调用 |
| 热键监听线程 | pynput 全局键盘钩子 | 只读状态 + `after` 投递，带防抖字典 |

其他健壮性保障：

- 执行引擎外层 `try/except/finally` 包裹 —— 任何异常都写入日志并强制复位「运行中」状态，界面永不卡死
- 悬浮窗引用采用局部变量快照，杜绝「检查后使用前被置空」的 TOCTOU 竞态
- 脚本加载全量校验（类型 / 字段 / 数值范围），坏数据在进入引擎前拦截

### 键盘发送路径对比

| 模式 | API 调用 | 每次按键事件数 | 适用场景 |
|------|----------|----------------|----------|
| 标准模式 | `SendInput(1)` VK 码单路 | 1 | 办公软件、网页、无引擎拦截的应用 |
| 游戏模式 | `SendInput(2)` Scancode + VK 原子双路 | 2 | DirectInput / Raw Input 游戏，兼容性最强 |

虚拟键码 → 扫描码由 `MapVirtualKeyW` 转换；扩展键（方向键、右 Ctrl/Alt/Shift、Insert/Delete 等）自动附加 `KEYEVENTF_EXTENDEDKEY` 标志。

### 鼠标发送路径

`SetCursorPos`（含 ±2px 随机落点）→ `SendInput` 按下 → 按压期微抖动（游戏模式）→ 保持 `duration` → `SendInput` 释放。点击事件不指定绝对坐标标志（`dx=dy=0`），在当前光标位置原地触发，避免二次坐标换算误差。

### 启动与提权流程

1. 程序启动，首先隐藏可能存在的终端窗口
2. 检测当前是否已具备管理员权限：是 → 直接进入主界面
3. 否 → 通过 `ShellExecuteW("runas", ...)` 以 `pythonw`、隐藏窗口方式发起 UAC 提权重启
4. 提权成功 → 新进程接管运行，旧进程退出；用户拒绝或提权失败 → 降级以普通权限继续运行，不会闪退

### 调试日志系统

键盘链路的关键节点（动作调度、VK 解析结果、Shift 组合、SendInput 成败、异常堆栈）默认写入脚本同目录的 `key_debug.log`，管理员/非管理员运行路径下均使用绝对路径定位。

- 高频「成功」类日志由源码顶部 `DEBUG_KEY_LOG` 开关控制（默认关闭以降低磁盘 I/O）
- 错误与诊断类日志始终写入，排查「按键无效果」问题时先看这份日志

## ❓ 常见问题（FAQ)

**Q1：点击 / 按键对游戏没有效果？**
A：按以下顺序排查：
1. 确认标题栏带有 **「(管理员模式)」** 字样 —— 没有则说明 UAC 被拒绝，重启并在弹窗中点「是」
2. 开启 **「游戏物理模式」**（默认开启），标准模式的 VK 单路对部分游戏引擎无效
3. 查看 `key_debug.log` 中是否有 `SendInput失败` 记录及其错误码
4. 个别带强反作弊的游戏对任何形式的模拟输入均有封号风险（见文末免责声明）

**Q2：双击 / 启动时闪出黑色终端窗口？**
A：v2.0 已全链路静默化：`bat` 走 `pythonw`，提权重启自动切换 `pythonw` 并以隐藏窗口方式拉起。若仍有闪烁，确认使用的是 `启动连点器.bat` 而非直接 `python main.py`。

**Q3：高 DPI 缩放（125%/150%）下坐标不准？**
A：程序已声明进程级 DPI 感知，坐标即屏幕物理像素。若目标应用本身是 DPI 虚拟化的旧程序，其窗口坐标体系可能不同，建议在 Windows 显示设置中对该程序单独关闭 DPI 缩放行为。

**Q4：按 `F10` 没反应？**
A：两种情况：① 正处于「录入按键」状态 —— 此时任意键都会被当作录入内容而非热键；② 1.5 秒防抖窗口内重复按 —— 等待防抖过期即可。

**Q5：运行中途修改「游戏物理模式」勾选为什么不生效？**
A：模式在点击「开始执行」时做值快照（保证线程安全），运行中切换需停止后重新开始才生效。

**Q6：脚本加载后部分动作消失？**
A：弹窗中列出了被过滤动作的具体原因（缺字段、类型未知、坐标非数字等），修正 JSON 后重新加载即可。

**Q7：无限循环怎么停？**
A：任意时刻按 `F10`、点击悬浮窗「■ 结束执行」，或关闭主窗口，均会立即中断当前动作链。

**Q8：每次打开都要重新导入配置文件吗？**
A：不需要。程序会自动记住你上次的动作序列和循环次数（存在 `last_session.json`），启动即恢复。只有想**切换到另一份已保存的脚本**时，才需要用「加载脚本」手动导入。
